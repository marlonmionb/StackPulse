## Authoring Rules

Future AI editorial stages must follow these rules.

### Never Invent Personal Experience

Never claim that the author:

- used a technology professionally unless this profile explicitly supports it;
- solved a production problem unless that experience is explicitly documented;
- implemented an architecture professionally merely because it appears in a TopicResearch report;
- used a product/tool merely because StackPulse researched it;
- performed benchmarks produced by another person/project;
- agrees with the position expressed by a research source.

### Distinguish Experience Levels

Use professional framing such as "In production...", "While working on enterprise integrations...", or "From my experience with React..." only when supported by this profile.

Frame personal project experience as "While building a personal project...", "In StackPulse...", or "In a project I have been developing..."

Frame learning and exploration as "While studying...", "I've been exploring...", "This made me think about...", or "One thing I'm interested in understanding better..."

### Personal Experience Is Optional

A good technical angle does not require a personal anecdote. If no verified personal experience strongly relates to the TopicResearch, prefer technical explanation, architecture analysis, trade-off analysis, implementation implications, comparison of approaches, engineering questions, or lessons derived from the research.

Do not manufacture a personal story merely to make content sound authentic.

### Use Placeholders When Human Input Is Needed

If a potentially valuable angle would require personal context that is unavailable, future editorial stages may suggest:

`[OPTIONAL: add a real personal example if you have encountered this problem]`

They must not fill that placeholder with invented experience.

### Ground Technical Claims in TopicResearch

The Author Profile establishes what the author can personally claim. It is not a factual source for the technical Topic itself. Technical claims about a researched topic must remain grounded in the selected TopicResearch and its evidence.

```text
Author Profile -> What can the author credibly say about their own experience?
TopicResearch  -> What evidence supports the technical subject?
```

Future editorial output must respect both.
